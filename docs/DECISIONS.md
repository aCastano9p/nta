# Decisions

Choices the brief left open. Newest at the bottom of each section.

## Tooling
- **Postgres port 55432** on 127.0.0.1 (5432/5433 were taken on the dev machine).
- **Driver: psycopg 3** (`psycopg[binary]`). A DB driver is required by SQLAlchemy; not a framework.
- **ULIDs generated in-process** (`nta/ids.py`, stdlib) instead of adding a ULID library. **Monotonic within a process**: IDs created in the same millisecond increment the random part, so id order = insertion order (allowlist replay depends on it; found via a flaky test).
- **Tests use a separate `nta_test` database**, dropped and rebuilt with `alembic upgrade head` once per pytest session, so the migration is tested too. Each test runs in a rolled-back transaction (rollback is not DELETE, so append-only still holds).

## Schema
- **Append-only trigger also blocks TRUNCATE** (statement-level), not just UPDATE/DELETE. Schema changes (DROP via Alembic downgrade) are still possible; that is deliberate, for dev resets.
- **runs has no `stopped_at` column; stops go to `run_stops(run_id, stopped_at, reason)`.** An append-only `runs` table cannot fill in `stopped_at` later. A crash leaves a run with no stop row, which is itself the crash signal. Added `runs.process` (`poll_edgar` | `quotes`) because both long-running processes record runs.
- **Allowlist versioning: rows are replayed in insertion order per FIGI.** A row without `removed_on` opens a membership interval; removing a ticker inserts a row with the same FIGI and `added_on` plus `removed_on`, which closes the newest open interval with that `added_on`. Active on day D iff `added_on <= D < removed_on` (or still open). Replaying in order, rather than grouping by `added_on`, makes a same-day remove + re-add work (bug found and fixed while correcting XOM).
- **CIKs stored zero-padded to 10 digits** (DB check constraint), matching EDGAR URLs.
- **`source_events` extra columns:** `items` (JSONB list of 8-K item numbers from the filing index, needed by the labeling tool), `primary_doc_url`, `raw_truncated`, `run_id`. `raw` holds the primary document as fetched (HTML, untrusted, never rendered); `raw_hash` is sha256 of the stored (capped) text. `raw` is nullable so a filing whose document fetch fails is still stored with its `first_observed_at` (rows cannot be filled in later).
- **`quotes` gets `first_observed_at` and `source_event_id`.** Quotes come from outside, so they carry both clocks (`ts` = Alpaca's timestamp, `first_observed_at` = ours). `source_event_id` links observe/mark quotes to their filing so moves are unambiguous when two filings hit one ticker; a check constraint requires it for every kind except `periodic`.
- **New table `quote_schedule(source_event_id, kind, due_at)`** persists pending observe/mark quotes. A schedule row is done when a quote with the same `(source_event_id, kind)` exists, so no update is ever needed.
- **New table `openfigi_responses`** caches OpenFIGI mapping responses in the DB (with `first_observed_at`), instead of a file cache, so provenance is kept.
- **Relabeling appends a new `labels` row; the latest per filing wins.** `labels.sample_seed` records the seed of the sampling session.
- **Enums are VARCHAR + CHECK** (not native Postgres enums), so adding a value later is a plain constraint swap.

## Allowlist loader
- **`.env` values with spaces must be quoted** (`SEC_USER_AGENT="Jane Doe jane@example.com"`) because the runbook loads it with `set -a; source .env`. The app reads only real environment variables; it does not parse `.env` itself.
- **Seed CSV `data/allowlist_dev.csv` is development data**: 20 US large caps picked by Claude, CIKs written from memory. Not the research allowlist; replace it with your CSV.
- **FIGI choice: the US composite FIGI of the common stock.** Query is `{"idType":"TICKER","idValue":<ticker>,"exchCode":"US"}`; keep results with marketSector=Equity and securityType2=Common Stock; exactly one distinct composite FIGI is required. Rejection reasons: `figi_not_found`, `figi_not_common_stock` (ETFs, ADRs, etc.), `figi_ambiguous`, `openfigi_error`, plus CSV problems (`invalid_ticker`, `invalid_cik`, `missing_name`, `duplicate_in_csv`) and `duplicate_figi`.
- **Share-class tickers**: `BRK.B` / `BRK-B` are sent to OpenFIGI as `BRK/B`; the ticker is stored as written in the CSV.
- **OpenFIGI rate limit**: no key, 25 requests per 60 s (confirmed from the `ratelimit-policy` header), 10 jobs per request. Token bucket 5 + 20/min. No API-key support (not needed at this volume).
- **OpenFIGI cache never expires.** FIGIs are permanent; a ticker moving to a new security (see XOM below) needs a manual remove + re-load anyway. Definitive answers ("found" and "not found") are cached; errors are not.
- **CIK cross-check against SEC `company_tickers.json` runs only when `SEC_USER_AGENT` is set** (it is a sec.gov request). Mismatches are rejected as `cik_mismatch` / `ticker_not_in_sec_list`. Without the env var the loader logs `allowlist_cik_check_skipped` and trusts the CSV. A wrong CIK would silently drop that ticker's filings for the whole window, so run the load with the variable set.
- **Loading only adds.** Tickers in the DB but not in the CSV are left alone; use `nta allowlist remove TICKER [--as-of DATE]`. Re-loading an already-active ticker is a no-op (`already_present`). Default membership date is today (`--as-of` to override).
- **Rate limiter is a token bucket with worst case `capacity + rate * window` per window.** SEC: capacity 2, rate 8/s, so any 1-second window holds at most 10. Every HTTP attempt, including retries, takes a token, so backoff cannot exceed the budget. Backoff is exponential with full jitter (base 1 s, cap 60 s, 6 attempts), and honors `Retry-After` up to 300 s; retried statuses are 429, 500, 502, 503, 504 and transport errors.

## EDGAR poller
- **One feed, both forms.** `type=8-K` on `getcurrent` returns 8-K and 8-K/A (and variants like 8-K12B). Stored forms: exactly `8-K` and `8-K/A`; others are ignored and counted as `other_form`.
- **Co-registrants.** One accession can appear once per filer (e.g. a REIT and its operating partnership). Entries are grouped by accession; the filing is stored if any of its CIKs is allowlisted, under that CIK.
- **`first_observed_at` = our clock right after the feed response arrives**, one stamp per feed page. The row is inserted after the index and document are fetched (append-only rules out filling `raw` in later). If the process dies in that window (normally under a second), the filing is re-observed on restart with a later stamp. Anything already stored is never re-stamped: it is in the DB-loaded `seen` set, and inserts use `ON CONFLICT DO NOTHING` on (source_id, accession).
- **Fetch failures still store the observation**, with `raw`/`raw_hash` NULL and a `filing_fetch_failed` log line. Losing the timestamp is worse than missing the document text.
- **Primary document = first row of the index's "Document Format Files" table whose Type equals the form type** (fallback: any `8-K*` row, then the first .htm/.txt). iXBRL viewer links (`/ix?doc=...`) are unwrapped to the raw document. **Exhibits (e.g. EX-99.1 press releases) are not fetched**, as the brief specifies the primary document; the labeling tool may want them later.
- **`raw` = the document as fetched (usually HTML), NULs stripped, capped at 2 MB on a UTF-8 boundary.** `raw_hash` = sha256 of the stored text.
- **Items** = union of the Atom summary's items and the index page's Items block, in that order.
- **`duplicate_seen`** counts, per poll and cumulatively, feed accessions already processed (stored, skipped as non-allowlisted, or lost an insert race). Logged in every `poll_ok` line and reported by `/healthz`.
- **Gap backfill.** If page 1 shares no accession with what we have seen, its oldest entry is newer than the newest stored filing, and the page is full, the poller reads further pages (`&start=100`, ...), up to 5 extra. In steady state page 1 always overlaps the previous poll, so this only fires after downtime or bursts of more than 100 8-Ks in 5 s. On an empty DB there is no anchor, so no backfill.
- **Allowlist is point-in-time by New York date**, refreshed every 60 s.
- **Poll interval is start-to-start** (5 s): a slow poll shortens the following sleep instead of adding to it.
- **HTTP timeouts: 10 s read, 5 s connect.** A live feed request once hung for a full read timeout; shorter timeouts keep a stall from delaying polls long.
- **`/healthz` on 127.0.0.1:8765** (stdlib `http.server`, own thread): JSON with `seconds_since_last_success`, poll counters, `duplicate_seen_total` and `run_id`. 200 if the last successful poll is at most 60 s old, else 503 (also before the first poll).
- **Runs.** `runs.code_sha` = git HEAD, suffixed `-dirty` if the tree has uncommitted changes. `config_hash` = sha256 of the effective non-secret config, which is also logged in `run_started`. A clean stop or a caught exception writes `run_stops`; a hard kill leaves none.
- **Signals.** SIGTERM/SIGINT set a lock-free flag; the current poll finishes, then the process exits and writes `run_stops`. Repeated SIGTERMs are ignored (`uv run` forwards SIGTERM, so `pkill -f` delivers two); a second Ctrl-C more than 1 s after the first forces exit. An earlier version called `threading.Event.set()` from the handler and deadlocked in a live test; signal handlers must not take locks.
- **XML parsing uses stdlib ElementTree** (no extra dependency). Python 3.12's bundled expat (>= 2.4) limits entity expansion, and ElementTree never resolves external entities.
- **Token bucket tolerance.** A refill can land at 0.9999999999999 tokens, whose remaining wait is too small to move a clock. The bucket treats >= 1 - 1e-9 as a full token and never sleeps less than 1 µs. Found as an intermittent test hang; covered by a regression test.

## Quote recorder
- **Snapshots endpoint only:** `GET https://data.alpaca.markets/v2/stocks/snapshots?feed=iex` gives the latest quote (bid/ask) and the latest trade (last) in one call, for up to 100 symbols. The client refuses any base URL other than `https://data.alpaca.markets`. Alpaca has no separate "paper data" host (paper and live share the data API); paper/live only differ on trading hosts, which are never configured.
- **Rate:** free plan is 200 requests/min; bucket 10 + 170/min. Requests time out after 5 s, with 4 attempts.
- **Quote fields:** `bid`/`ask` from the latest quote (0 = no quote on that side, stored as NULL; a crossed quote is dropped), `last` = latest trade price, `ts` = the newer of the quote and trade timestamps, `first_observed_at` = our clock right after the response.
- **Observe quote:** during market hours it is due at `first_observed_at`; the recorder checks the DB every 0.5 s, so it normally lands well within 2 s. **Outside market hours the observe quote is taken at the next regular-session open** (the brief only defines the in-hours case).
- **Marks are anchored on the observe time, not the raw `first_observed_at`.** `mark_1h` = observe + 1 h, rolled to the next open if that is outside a session. `mark_1d` / `mark_5d` = the same New York time of day, 1 / 5 *trading sessions* later, clamped to 1 minute before an early close. Reason: most 8-Ks are filed after 16:00; with a literal "first_observed_at + 1 h, rolled forward" the observe and the 1-h mark would both land on the next open and the 1-h move would always be zero. "1d / 5d" read as trading days, which is the usual market meaning; a calendar reading would make "5d" mean 3 trading days for a Friday filing.
- **Consequence:** for after-hours filings, moves measured from the observe quote exclude the overnight gap (close -> next open). The verdict CSV includes the last periodic quote before the filing so the gap can be analysed later.
- **Persisted schedule:** `quote_schedule` rows (observe + 3 marks) are written when the recorder first sees a filing; a row is done when a quote with the same `(source_event_id, kind)` exists. Due rows are only executed while the market is open; anything that came due while the recorder was down is executed late at the next open, and the verdict ignores marks recorded more than 10 minutes after their due time.
- **Missing symbols** (no usable quote or trade in the snapshot) are retried every 5 s, so one bad symbol cannot burn the request budget.
- **Periodic quotes:** once per 5-minute wall-clock slot (09:30, 09:35, ...) during the regular session, for every instrument in the allowlist that day. After a restart the recorder resumes from the last stored slot, so a slot is not recorded twice.
- **Market calendar:** `pandas_market_calendars` XNYS (holidays and early closes). Scheduling is pure (`nta/marketcal.py`) and tested across a weekend, Thanksgiving, the following early close and the Nov 1 DST change.

## Labeling tool
- **Sample = the `target` filings with the smallest `sha256("<seed>:<accession>")`**, labeled in that order. A filing's rank does not depend on which other filings exist, so a session resumes in the same order and the queue is stable. Default seed 7, target 100; `--start/--end` restrict to a window (New York date of first observation). Sample after the window closes: while collection is running, new filings can still enter the top 100.
- **Population = every stored EDGAR filing in the window** (8-K and 8-K/A).
- **Preview starts at the first "Item X.XX" heading, not the top of the document.** The first ~60 lines of an 8-K are cover-page boilerplate (seen on a real P&G filing), so a literal "first 60 lines" would rarely show the substance. The tool prints how many cover lines were skipped and falls back to the top if there is no Item heading. HTML is converted to text (scripts, styles and hidden iXBRL headers dropped).
- **Terminal safety:** filing text has C0/C1 control characters (including ESC), zero-width characters and bidi overrides removed before printing.
- **Answers:** material y/n; direction only asked when material (non-material is stored as `unclear`); event_type always asked (number 1-7 or name); note optional. `s` skips (asked again next session), `q` or Ctrl-D quits. Item numbers are shown with their official titles.
- **Labels are rows, never edits.** Relabeling (not exposed in the CLI) would append a row; the verdict uses the latest label per filing.

## Verdict
- **Window** = New York dates of `first_observed_at`, inclusive; default first to last stored filing. `--start/--end` override.
- **Price = mid only when the quote is tight (spread <= 20 bps of the mid); otherwise the last trade** (decided with the user on 2026-11-02, replacing the brief's "mid, or last if no bid/ask"). Reason: the free plan's IEX quotes show only IEX's own book. A live snapshot on 2026-11-02 had JPM, MA and PG with 500-600 bps spreads and mids 2.5-2.9% away from the last trade, which would swamp the 30 bps threshold. A wide quote with no trade has no price (the move counts as missing). The rule runs at verdict time on the stored bid/ask/last, so it can be changed later without re-collecting. The verdict prints how many prices came from each source, and the CSV has a `*_source` column per price.
- **Move** = mark price / observe price - 1, in bps; stats use the absolute value, the CSV keeps the sign. A quote recorded more than 10 minutes after its due time is not used (counted as "excluded"); a mark with no quote is "missing". Both counts are printed.
- **Percentiles** use linear interpolation between closest ranks (numpy's default); IQR = p25-p75.
- **Material filings per month** = filings observed in the window x material share of the labeled sample x 30.4375 / window calendar days. Interval = 95% Wilson interval of the share, scaled the same way (no finite-population correction, so it is slightly conservative when the sample is a large part of the window).
- **The disproof condition uses point estimates**, verbatim: STOP if the median |1d move| of labeled-material filings < 30 bps, or material filings per month < 60. If either quantity cannot be computed (no labels, no usable 1-day moves), the verdict is STOP with the reason printed: the idea has not shown it clears the bar.
- **"Observe quote > 5 s after first_observed_at" is reported over filings observed during market hours.** Filings first seen outside hours have their observe quote at the next open by design, so they would all count as late; they are reported as a separate count.
- **Splits** by event_type and direction are over material filings; "all filings" and "labeled" rows are added for context.
- **CSV** goes to `exports/verdict_<start>_<end>.csv` by default (git-ignored); prices with 4 decimals; includes `pre_filing_price` (last periodic quote before the filing) so the overnight gap can be studied later.
- **Fixture first:** `tests/fixtures/verdict/fixture.json` (10 filings) with the expected answers worked out by hand in `tests/test_verdict.py`'s docstring. The code matched all of them on its first run.

## Dashboard
- **Added at the user's request (2026-11-01), overriding the brief's "no web UI" rule.** Kept inside the brief's other constraints: no new dependencies (stdlib `http.server`, server-rendered HTML), read-only (GET only, no forms, no writes), bound to 127.0.0.1.
- **No JavaScript.** Auto-refresh every 15 s via `<meta http-equiv="refresh">`. CSP `default-src 'none'; style-src 'unsafe-inline'` blocks any script even if escaping were to fail.
- **Untrusted content:** every DB value is HTML-escaped; filing text is shown only as escaped plain text in `<pre>`; only `https://www.sec.gov/...` URLs become links.
- **Process status** comes from probing the poller's and recorder's `/healthz` (0.4 s timeout); runs with no `run_stops` row that are not the live process are flagged "no clean stop".
- **Verdict panel** reuses `nta.verdict.compute` over the default window, marked *provisional* until there are 30 trading days and 100 labels.
- **Demo mode (`--demo`)** drops and rebuilds a separate database, `nta_demo`, with a synthetic 30-trading-day dataset (deterministic seed) and shows a "Demo data" banner. It refuses to run if `DATABASE_URL` itself points at `nta_demo`. Synthetic filings link nowhere (`demo.invalid` URLs).
- **Bug found while checking against the real dev DB:** the per-day chart dropped weekends, so a database whose only filing was seen on a Sunday crashed the page. Weekend days with filings are now kept (regression test added).

## Throughput (2026-11-02)
- **Alpaca snapshot chunks (100 symbols each) are fetched concurrently**, up to 5 at a time, so a 500-ticker periodic quote is one round trip instead of five sequential ones and cannot delay observe quotes. The shared token bucket still caps the rate; a failed chunk fails the whole call, which is retried on the next tick.
- **OpenFIGI is not parallelized:** its limit is on requests per minute, so concurrent requests would only produce 429s. Instead, an **optional `OPENFIGI_API_KEY`** (free) raises the limits from 25 req/min of 10 tickers to 250 req/min (confirmed from the `ratelimit-policy: 250;w=60` header on 2026-11-02) of 100 tickers. Bucket 5 + 20 per 6 s, so at most 205 requests in any 60 s window. Without the key nothing changes. Answers are cached, so this only matters for the first load of a large allowlist.

## Phase 1 schema (migration 0002)
- **Tables beyond the brief's list:** `risk_reviews` (exactly one per trade decision: nta risk's approve/reject with its own quote, so a risk rejection leaves a row and no order), `grades` (rubric scores, `grader` = llm | human, latest per grader wins), `estimates` (the estimate ledger, kept apart from real P&L).
- **Quote kinds `decision` and `manage`** added to `quotes.kind`. Every quote the agent acts on (entry decision, position-manager check) is stored like any outside data, so replay can use exactly what live saw. The verdict reads only observe/mark kinds of EDGAR events, so it is unaffected.
- **`decisions` holds no free text** (reasons are codes; quote, exposure and plan are numbers). nta risk may therefore read any decisions column. Free text (headline, thesis, contrary evidence) lives in `signals.extraction` / `signals.headline` and `llm_calls`.
- **One entry decision per signal** is a partial unique index (`signal_id WHERE kind = 'entry'`). Close decisions point at their entry through `parent_decision_id`; a failed close may be followed by another close decision.
- **A trade decision must be complete** (side, qty > 0, plan) by check constraint, so "the row is complete before anything reads it" holds at the DB level.
- **Incidents have no resolved flag.** An incident is open until the next human `resume` (a `RUN` row in `kill_switch_events` after it). Append-only rules out flipping a flag.
- **`fills` are one row per increase of an order's cumulative filled quantity**, unique on `(order_id, cum_qty)`, so re-polling an order can never double-count a fill.
- **Nullable JSONB columns store SQL NULL for Python `None`** (`JSONB(none_as_null=True)`); plain JSONB writes JSON `null`, which silently passed an `IS NOT NULL` check in the first test run.

## Policy file
- **`policy/policy.yaml` is read once at startup**; a change takes effect when the processes restart (each start writes a `policy_versions` row). `policy_version` = sha256 of the file bytes, so a comment edit is a new version too.
- **Strict schema** (`nta/policy.py`, pydantic, unknown keys rejected). `long_only` is typed `Literal[True]`: the file cannot switch shorts on.
- **Signing:** nta risk HMAC-SHA256s `"policy:<hash>"` with `RISK_SIGNING_KEY` (only nta risk has it) and writes a signed row. nta agent writes an unsigned row for what it saw. nta risk rejects any decision whose `policy_version` differs from the hash it signed (`policy_mismatch`), so an agent running on an edited file cannot get an order through.
- **Percent values are in percent** (`risk_unit_pct: 0.25` = 0.25 %), spreads and costs in bps.
- **Source kinds** for latency budget and horizon: `filing` (EDGAR, 60 min / 2 trading days, as briefed) and `post` (X, 10 min / 1 trading day; the brief gives no post values, so these are guesses to revisit with data).
- **Sector map lives in the policy file** (`sectors:` ticker -> GICS sector, filled for the 20 dev tickers). It changes what the sector cap allows, so it is versioned with the limits. Unlisted tickers count as sector `unknown` (one shared bucket, which is conservative).
- **Limits the brief did not name**, all in the file: `take_profit_r` 2 (take-profit at 2 R), `min_p_up` 0.6, entry/exit marketable-limit offsets (10 / 50 bps), `entry_ttl_s` 60, cost model (5 bps assumed spread when unverified, 5 bps slippage, 0.5 bps fees), blackout minutes after open / before close plus explicit windows, clustering and corroboration thresholds.
- **Quote source (`quote_source: iex | sip`).** Phase 0 measured IEX spreads past 500 bps on JPM, MA and PG, which makes a 20 bps spread check meaningless on the free feed. With `iex` (default, free) the spread check is skipped in favour of the last trade, the decision is flagged `spread_unverified = true`, and the cost model uses `assumed_spread_bps_unverified`. With `sip` (Alpaca Algo Trader Plus, USD 99/month) agent and risk request the SIP feed and check the NBBO spread against `spread_limit_bps`. The dashboard shows the share of flagged decisions. The phase 0 quote recorder stays on IEX regardless, so the verdict's data does not change.

## Clustering
- **Headline for an EDGAR filing** = company name + form type + item numbers with their official titles (e.g. "Apple Inc. 8-K items 5.02 Departure of Directors..."). 8-Ks have no headline, and this text is deterministic, needs no LLM, and makes an 8-K/A of the same items cluster with its original. For an X post the headline is the post text.
- **MinHash:** character 4-gram shingles of the normalized headline (lowercase, URLs dropped, punctuation to spaces), 64 permutations, each a seeded blake2b-64 hash (stdlib, deterministic across processes and runs, which replay needs). Same cluster when estimated Jaccard >= `clustering.minhash_threshold` (0.5).
- **Join order:** within the 72 h window, an item that cites an earlier item's accession number (plain `0000320193-26-000011` or inside an `sec.gov/Archives/edgar/data/...` URL) joins that item's cluster first; otherwise the earliest earlier item with the same event type, same instrument and similar headline. Otherwise it starts a cluster. Joining = repeat.
- **`cluster_id` = the source_event id of the cluster's first member** (not a signal id). Source events are inputs, so the id is the same when replay re-derives the signals; decision content hashes can then include it.
- **Citations are found by regex on the item's text**, plus the model's `cited_origin` field when it contains an accession. The regex keeps EDGAR-citation clustering deterministic even if the model misses it.
- **Corroborated** iff the cluster contains a `primary` source (every EDGAR filing) or has at least `corroboration.min_origins` (2) distinct origins whose weights (max per origin) sum to at least `min_weight` (1.0). An origin is `edgar` or `x:<author_id>`, so one account posting twice counts once.
- **Event type for clustering** comes from the extraction, or from triage when extraction did not run, or `unknown` when neither produced one.
- **Consequence:** two unrelated 8-Ks from the same company with the same items within 72 h (e.g. two "8.01 Other Events") cluster as a repeat and the second is not traded. Accepted for now: the cost is a missed trade, never a doubled one.

## LLM extraction
- **No `temperature: 0`.** The brief asks for temperature 0, but the current API rejects sampling parameters on Haiku 5.5 and Sonnet 5.5 (non-default values return 400; the installed SDK, `anthropic` 2.3.0, no longer has the parameter). Reproducibility comes from the cache instead: every request is hashed and a stored answer is never re-requested, and replay only reads the cache. Requests set `output_config.effort` (triage `low`, extraction `medium`) and leave thinking at the model default (adaptive).
- **Structured output via `output_config.format` (JSON schema) on `messages.create`**, not `messages.parse`, so `llm_calls.response` holds the raw API response. Our own pydantic models (`Triage`, `Extraction`) validate the text with `extra="forbid"` and range checks; anything that fails (extra fields, `p_up_at_horizon` outside [0, 1], non-JSON, `stop_reason` refusal or max_tokens) is discarded and the signal is an abstention (`llm_invalid`).
- **Two steps:** triage (`claude-haiku-5-5`, `prompts/triage_v1.md`: material?, event type) on every item; extraction (`claude-sonnet-5-5`, `prompts/extract_v1.md`) only when triage says material. Not material = signal status `triage_rejected`. Models from `LLM_TRIAGE_MODEL` / `LLM_EXTRACT_MODEL`. `decisions.prompt_version` = `triage_v1+extract_v1`, `model_id` = `<triage model>+<extract model>`.
- **Prompt injection:** the system prompt is the prompt file, byte for byte. All third-party text (document, 8-K items, post, plus the metadata line) goes inside one `<untrusted_item>` block in the single user turn; any `<untrusted_item` / `</untrusted_item` in the text is HTML-escaped so it cannot close the block. The prompts say the block is data and that embedded instructions mark the item as not credible. Quantity and symbol never come from the model: the symbol comes from the CIK, the quantity from the policy formula.
- **Request hash** = sha256 of canonical JSON (sorted keys) of `{prompt_version, request}`, where request is exactly what is sent (model, max_tokens, system, messages, output_config). Unique in `llm_calls`.
- **Transport errors are stored too** (`response` NULL, `error` text, `valid` false, cost 0). Otherwise replay would hit a cache miss where live abstained. The SDK retries twice first (60 s timeout).
- **Budget:** `LLM_DAILY_USD` (default 5) caps the sum of `llm_calls.cost_usd` since New York midnight. Checked before each uncached call; when spent >= cap the call is not made and the signal is abstained with `llm_budget`. A call already under way can overshoot the cap by its own cost. Cost = tokens x first-party list price per model (Haiku 5.5 $0.10/$0.50, Sonnet 5.5 $2/$10 per MTok; unknown models priced as Opus 5.5 so a typo cannot under-count).
- **Document text** = the stored primary document as plain text (`label.html_to_lines`), capped at 40,000 characters, with a note in the metadata when truncated. Exhibits (EX-99.1 press releases) are still not fetched (phase 0 decision), so many 8-Ks will triage as not material or extract as `unclear`; fetching the exhibit is the obvious next improvement.

## Decision engine (`nta/decide.py`, `nta/agent.py`)
- **Outcomes.** `trade` = every check passed. `wait` = only market-state reasons failed (`market_closed`, `scheduled_blackout`, `kill_switch`, `quote_missing`, `quote_stale`, `spread_wide`, `no_equity`): the news might be tradeable, the moment is not. `abstain` = any judgment or policy reason (`unclear`, `low_conviction`, `long_only`, `repeat`, `uncorroborated`, `late`, `already_priced`, `cap_hit`, signal-level `not_material` / `llm_*` / `no_instrument` / `injection_suspected`). Both are final: one entry decision per signal, never re-decided. All failing reasons are recorded, not just the first.
- **Reason codes beyond the brief's list:** `unclear` (direction unclear), `low_conviction` (`p_up_at_horizon` < `min_p_up` 0.6), `repeat` (cluster already seen in 72 h: never trade the same news twice), `market_closed`, `kill_switch`, `quote_missing`, `no_equity`, the signal-level codes above.
- **Evaluation time.** A tradeable-in-substance signal gets a fresh snapshot from account D's feed, stored as quote kind `decision`; every check runs "as of" that quote's `first_observed_at`, which is also `decided_at`. Signals rejected before a quote is needed (not material, LLM failure, injection flag, no instrument) are decided as of the signal's `ready_at` and fetch nothing.
- **Reference price.** IEX: the last trade (its book is too thin). SIP: the ask for a buy. Stop, take-profit, limit and the already-priced check all use it.
- **ATR and volatility come from the recorded 5-minute periodic quotes**, not bars: ATR = mean absolute change between consecutive periodic prices (last 14, pairs more than 10 minutes apart skipped, so overnight gaps do not count); daily vol = std dev of those 5-minute log returns x sqrt(78), falling back to `default_daily_vol_pct` (2 %) with fewer than 20 returns. Both are pure functions of logged data, so replay reproduces them; no high/low exists in the log. No ATR (too little history) means the 1 % minimum stop applies.
- **already_priced:** reference = the event's observe quote (phase 0 recorder) if recorded by then, else the last quote of the instrument at or before `first_observed_at`. Elapsed time is floored at 5 minutes; without the floor a decision 20 s after a filing would flag 6 bps of quote noise as "priced". No reference price = PASS.
- **Sizing:** `floor(risk_unit x equity / stop distance)`, then capped by position (10 %, including any existing position in the symbol), cluster (15 %), sector (25 %) and the 5-open-positions limit; a result below 1 share is `cap_hit`. Note the default policy's position cap binds before the risk unit for any stop under 2.5 % (0.25 % risk / 10 % cap). Exposure is measured at cost basis from fills, so it does not depend on later quotes.
- **Exposure and equity are point-in-time:** positions from `fills` with `first_observed_at <= as_of` (close fills reduce their entry), equity from the latest account-T `position_snapshots` row at or before `as_of` (written by nta risk). No snapshot yet = `no_equity` (wait), so the agent never sizes before nta risk has run.
- **Expiry** = the same New York time of day `horizon_trading_days` sessions later, at least 5 minutes before that session's close (handles early closes).
- **Expected cost (round trip)** = spread (measured on SIP, `assumed_spread_bps_unverified` on IEX) + 2 x slippage + fees.
- **Long only:** a `down` signal is abstained with `long_only` and the mirrored short plan is stored in `hypothetical`.
- **Content hash** = sha256 of canonical JSON (sorted keys) of the decision content (kind, source event, instrument, symbol, cluster, outcome, reasons, side, qty, quote without its row id, exposure, plan, expected cost, spread flag, hypothetical) plus policy, prompt and model versions. Left out: row ids (replay writes its own rows), `decided_at` (the quote timestamps inside the payload already pin the time), `code_sha` (a refactor that changes nothing must replay identically) and `data_snapshot` (an event stamped before `as_of` can commit just after the read; recorded for audit, not compared).
- **Injection flag.** A deterministic regex for instruction-like text addressed to a model ("ignore previous instructions", "you are now", "system prompt", a stray `<untrusted_item` tag...) sets `signals.flags = ["injection_suspected"]`; such a signal is abstained even when the model returned schema-valid output, and no quote is fetched. The model is still called (its answer is recorded). Defense in depth on top of the data-block isolation; buyback language like "repurchase up to 1,000,000 shares" is not flagged.
- **The agent processes only source events first observed in the last 24 h** (`--lookback-h`): after downtime, old filings would only produce `late` abstentions and LLM spend. Replay processes every event in its window.
- **Signals are decided right after they are written**; a second pass decides any signal a crash left without a decision.
- **Agent credentials:** `nta agent` exits with code 2 before reading anything else if `ALPACA_TRADING_KEY_ID`, `ALPACA_TRADING_SECRET` or `RISK_SIGNING_KEY` is set. It reads account D's keys (`ALPACA_KEY_ID` / `ALPACA_SECRET`, the same pair `nta quotes` uses) and `ANTHROPIC_API_KEY`. `/healthz` on 127.0.0.1:8767.

## Risk service and executor (`nta/risk.py`, `nta/broker.py`)
- **Credentials.** Account D keeps the phase 0 variables `ALPACA_KEY_ID` / `ALPACA_SECRET` (used by `nta quotes` and `nta agent` for data). Account T is `ALPACA_TRADING_KEY_ID` / `ALPACA_TRADING_SECRET`; together with `RISK_SIGNING_KEY` (>= 32 chars) they exist only in nta risk's environment. nta risk exits with code 2 if any `ANTHROPIC_*` variable is set (that covers API keys, auth tokens, profiles and federation variables, since the SDK resolves all of them), or if the T key id equals the D key id.
- **nta risk also reads account D's keys**, only for the watchdog (GET orders and positions on the paper trading API). Using D's key pair outside agent/quotes is unavoidable for a watchdog of account D; it never places orders with it.
- **Paper only:** the trading client refuses any base URL other than `https://paper-api.alpaca.markets`. Orders are day limit orders.
- **Order POST is sent exactly once.** A timeout, transport error or 5xx raises `BrokerTimeout`; the executor then looks the order up by `client_order_id`. Found = `found_on_lookup`; not found = `submit_timeout`, and the next tick looks up again before any new attempt. A 422 for a duplicate client order id is also resolved by lookup. Other 4xx = `broker_rejected` (final, no retry).
- **The executor always looks up before submitting**, not only after a timeout. One extra GET per order buys "a restart never re-sends blindly" without having to know where the previous process died.
- **`client_order_id` = `nta-<decision_id>-<leg>`** (31 characters). Every decision has one leg (`1`); a failed close is followed by a new close decision, hence a new id.
- **HMAC-SHA256 over `order:<decision_id>|<side>|<qty>|<limit with 4 decimals>`** with `RISK_SIGNING_KEY`. Signing and verifying both live in nta risk; the point is that a row inserted into `orders` by anything else (agent, a person with DB access, a bug) is never sent. An invalid HMAC writes `hmac_invalid`, a severity-1 incident and PAUSE. The executor also refuses an order whose decision is not a `trade` (`no_trade_decision`, severity 1).
- **Risk review (one `risk_reviews` row per trade decision), with its own quote from account T's feed and account T's real positions and equity:** `policy_mismatch` (decision made under another policy file), `decision_stale` (entry decided more than 30 s ago, e.g. risk was down), `kill_switch`, `market_closed`, `long_only`, `quote_missing` / `quote_stale` / `spread_wide` (SIP only), `price_above_limit` (the price ran past the planned limit), `price_below_stop`, `daily_loss_stop` (equity <= last close equity x (1 - 1 %)), `drawdown_pause` (equity <= peak snapshot equity x (1 - 5 %); also raises an incident, which sets PAUSE), `max_open_positions`, `cap_hit`. Caps are recomputed on broker positions valued at the risk quote; risk may lower the quantity (it signs its own quantity), never raise it.
- **Closes:** allowed in RUN, PAUSE and FLATTEN, blocked in HALT. Quantity = min(decision qty, what the log says that entry holds, what account T holds), so a close can never open a short. Limit = last trade (or bid) x (1 - `exit_limit_bps`).
- **Kill switch semantics.** PAUSE: no new entries (agent waits, risk rejects and the executor blocks unsent entry orders); closes continue. FLATTEN: as PAUSE, plus nta risk writes a close decision (reason `flatten`, prompt/model version `none`) for every open position without a pending close; so the invariant "no order without a decision row" holds for flatten orders too. HALT: nothing is sent, not even closes, and every open broker order is cancelled each tick. RUN is written only by `nta kill resume`, which lists open incidents and requires typing `RESUME`; processes only ever write PAUSE.
- **Partial fills:** each sync compares the broker's cumulative filled quantity with the log; an increase becomes one `fills` row with qty = delta and price derived from the change in average fill price. Unfilled entry orders are cancelled after `entry_ttl_s` (60 s); exits are left working (day orders expire at the close).
- **Incidents** are deduplicated per kind until the next human resume, so a persistent condition does not write a row every tick.
- **Enforcement that nta risk never reads free text** is by construction (explicit column lists; decisions hold no free text) and by test: every SELECT issued during a risk tick is captured and checked for `signals`, `llm_calls`, `source_events`, `labels` and free-text columns. A second test imports `nta.risk` and `nta.cli` in a fresh interpreter and checks that neither `anthropic` nor `nta.extract` / `nta.agent` got loaded.

## Reconciler and watchdog (inside nta risk)
- **Order of a reconcile:** sync working orders first (so a fill that happened since the last tick is in the log), then compare account T's positions per symbol with the log (sum of fills) and account T's open orders with `orders.client_order_id`. A position difference in any symbol, or an open order the log does not know, is a mismatch. Every cycle writes a `position_snapshots` row (account T: equity, last close equity, cash, broker positions, open order ids, log positions, mismatch flag, details).
- **Mismatch = incident `reconcile_mismatch` (severity 2) + PAUSE** (actor `reconciler`, linked to the incident). PAUSE lets closes through, so existing positions keep their stops. The incident stays open (and is not re-raised) until a human resumes.
- **Startup:** nothing is reviewed or sent until one reconcile has succeeded; if the broker is unreachable at startup, the tick does nothing and retries. After that, every 30 s; a failing reconcile is logged (`reconcile_failed`) and does not block closes.
- **Account T must be dedicated to NTA and flat at first start:** any position not created by NTA's orders is a mismatch by design.
- **Watchdog (every 30 s):** account D's positions and open orders via the paper trading API with D's keys; a `position_snapshots` row with `account = 'D'`; anything there = incident `account_d_activity`, severity 1, + PAUSE (actor `watchdog`).
- **`/healthz` (127.0.0.1:8768)** lists the kill switch state and open incidents and answers 503 while any incident is open or before the first reconcile, in addition to the usual staleness rule. `HealthServer` gained an optional `unhealthy` flag for this.
- **Quantities in snapshots are normalized strings** (`"49"`, not `"49.000000"`).

## Position manager (inside nta agent)
- **Open positions come from fills** (`load_positions`, the same loader the decision engine uses), each attributed to its entry decision, whose plan holds stop, take-profit and expiry.
- **Every 5 s during market hours**, for each open position without a pending close, the agent fetches a snapshot from account D's feed (stored as quote kind `manage`) and checks, in order: price <= stop -> `stop`, price >= take-profit -> `take_profit`, quote time >= expiry -> `expiry`. Exit price = last trade on IEX, bid on SIP.
- **A trigger writes a close decision** (kind `close`, outcome `trade`, reason = the trigger, qty = the position, quote and trigger price recorded, same version tuple as entries) with `parent_decision_id` = the entry. nta risk reviews and executes it like any order, capping the quantity at what is actually held.
- **Kill switch:** the manager keeps running in PAUSE and FLATTEN (FLATTEN's own close decisions count as pending, so the manager does not double them) and stands down in HALT, where nta risk would refuse closes anyway.
- **Outside market hours nothing is checked:** a close could not fill, and an expiry that passes overnight fires at the next open.
- **Retry:** if a close is rejected or its order dies unfilled, the manager writes a new close decision for the position after 60 s, not every tick.

## Evaluation (`nta evaluate`, `nta label --review`)
- **Due** = entry decisions with a plan whose expiry has passed and no postmortem yet. A trade whose position is still open waits for the close, or one day after expiry, whichever comes first (then the open part is marked at the last recorded price). Signal-level abstentions (no quote, no plan) are not evaluated: there is no horizon or price to judge them against.
- **Frozen packet** = the decision row, its source event (metadata plus the first 12,000 characters of text), signal (extraction, cluster, flags), the exact triage and extraction `llm_calls` rows (request and response), quotes of the instrument observed in the 2 hours up to `decided_at`, and the version tuple. Nothing observed after `decided_at`. Stored in `postmortems.packet` with its sha256.
- **LLM grade** (`prompts/grade_v1.md`, `claude-sonnet-5-5` or `LLM_GRADE_MODEL`, through the same cached, budgeted gateway; purpose `grade`): the grader sees the packet without the raw request bodies (the document is already in it) inside the untrusted data block; it never sees fills, exits or P&L. Six integer scores 0-2 (enum in the output schema) plus a short rationale (validated, not stored in `grades`; it is in `llm_calls`). Only decisions whose signal was extracted are graded. A failed or budget-capped grade leaves the postmortem without quality.
- **Quality:** sound = total >= 9 and no zero; unsound = any zero or total <= 6; insufficient = otherwise (7-8 without a zero). **Result:** win / loss / flat (flat = within 1 bp of notional), from real net P&L for trades, from the estimate ledger for abstentions. **Quadrant** = `<quality>_<result>`, e.g. `sound_loss` (bad luck), `unsound_win` (luck).
- **Execution metrics:** decide->submit (first `submitted` / `found_on_lookup` event), submit->first fill, slippage of the average entry fill vs the decision mid (IEX: the last trade), fill ratio, entry vs planned limit in bps, filled vs planned quantity, exit triggers. **Economic:** gross and net P&L (fees = `fee_bps` on entry notional, the same round-trip number the cost model uses; Alpaca charges no commission), net bps, MAE/MFE from recorded prices between first fill and exit, SPY return over the same window from Alpaca 1-minute bars (data API, account D), tail flag when the net loss exceeds 2 x the plan's risk unit in USD.
- **Estimate ledger:** for abstentions with `late`, `already_priced`, `cap_hit` or `uncorroborated`, a long simulated on recorded prices of any quote kind after `decided_at`: entry at the plan's reference price, exit at the first price at or below the stop (at the observed price if it gapped through), at or above the take-profit (at the take-profit), or the last price before expiry; net of the decision's expected cost. Quantity = the plan's, or the uncapped risk-unit quantity when the cap left zero. Flagged `uncertain` when prices are more than 30 minutes apart.
- **Guardrail proposals** (rows only, once per rule per policy version): `tail_losses` (>= 2 tail losses in the last 20 evaluated trades -> propose halving `risk_unit_pct`) and `already_priced_k` (>= 10 `already_priced` estimates with a positive mean net -> propose k + 0.5). A test checks that nothing in the package writes any file except the verdict CSV, so no code path can edit the policy.
- **Human review** (`nta label --review`): the queue is a seeded 20 % of LLM-graded decisions (ranked by `sha256("<seed>:<decision_id>")`, so it resumes in order) plus every decision whose LLM grade has a zero. The terminal shows the frozen packet only (no fills, P&L or later prices), sanitized; six scores 0-2; `q` stops; grades are rows with `grader = human` (latest wins).
- **Agreement:** Cohen's kappa over decisions graded by both, for the quality label and for all criterion scores pooled.
- **`nta evaluate` runs with agent-side credentials** (account D for bars, the LLM key for grading) and refuses trading credentials like `nta agent`. `--no-grade` skips the LLM.
